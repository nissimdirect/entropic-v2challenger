# Pattern teardown: selection

Scope: how Creatrix selects, extends, toggles, ranges and clears things (clips, tracks, effects, time ranges, mask regions) and how the references model it. Feeds systems/selection and O02 O03 O06 O08 (also O09 for the time-range selection, D12).
Legal tiers: React Aria / Apache-2.0 = ADOPT (code read freely). Blender and Ardour = GPL, READ for patterns only; every GPL row below is a behavior description in our own words, no code copied.
Refs cloned at `~/Development/_refs/{react-spectrum,blender,ardour}` (read-only, never executed).

## Problem in Creatrix today

1. **Selection is five unrelated pieces of state with no shared model.** `selectedTrackId`, `selectedClipId` (deprecated alias), `selectedClipIds`, `selectionRegion` all live in `frontend/src/renderer/stores/timeline.ts:166-169,843-849`; effect selection is `selectedEffectId` in the project store (read in the Delete handlers `App.tsx:938-957,1149-1160`); mask selection is separate again. Delete/Escape each have to know which one to act on (`App.tsx:1069-1085`, `Timeline.tsx:105-113`).
2. **`selectedClipId` is derived as `selectedClipIds[0]`** after every mutation (`stores/timeline.ts:2462-2523`), but a toggle that removes the first id silently changes which clip is "the" selected one. There is no active/anchor concept: `rangeSelectClips` in `Clip.tsx:479-481` uses `selectedClipIds[selectedClipIds.length-1]` as the anchor, i.e. "last toggled", which is order-of-click dependent and is not preserved across a toggle-off.
3. **Range select is by flat clip order, not geometry.** `rangeSelectClips` slices `getAllClipsInOrder(tracks)` (`stores/timeline.ts:2476-2488`): Shift-click across two tracks selects every clip in track-array order between the two, which is not the rectangle the user sees.
4. **Modifier meaning is inconsistent between gestures.** On a clip, Cmd/Ctrl = toggle, Shift = range (`Clip.tsx:476-485`). On the same pointerdown Cmd/Ctrl also means "bypass snapping" while dragging (`Clip.tsx:40-45,499,625,651`), so Cmd-click-toggle then dragging un-snaps. On the marquee, `Alt` = snap bypass (`MarqueeOverlay.tsx:141,154`, D12). The inventory lists 54 modifier checks (`inventory.json` `modifierSites`); no document maps them.
5. **Right-click selects only if not already selected** (`Clip.tsx:205-214`), which is the right rule, but the same rule is not applied to tracks, devices or automation points (each `onContextMenu` in `inventory.json` `contextMenus`, 40 sites, is hand-rolled).
6. **Menu promises a shortcut that does not exist:** Select menu "Select All Clips" is labelled `CmdOrCtrl+A` (`frontend/src/main/menu.ts:61`) but `DEFAULT_SHORTCUTS` has no `meta+a` (`default-shortcuts.ts`, grep) and menu items deliberately carry no accelerator (`menu.ts:17-20`), so Cmd+A does nothing from the keyboard; only the menu click works (`app/menuActions.ts:76`). `Deselect All` / `Invert Selection` have no keys at all (`menu.ts:62-63`).
7. **Escape clears selection in only one context.** Perform-armed Escape clears clips then panics (`App.tsx:1069-1085`); otherwise Escape only cancels a marquee drag or clears `selectionRegion` (`Timeline.tsx:105-113`) and never clears `selectedClipIds`. No ordered "Escape ladder".
8. **Translucency = selection (D11)** is law, but selection visuals are per-component CSS; no single spec of which state shows which treatment.

## Recommendation for the spec

1. Define one **Selection model** per selectable kind with fields `{ keys: Set, anchor, current }` and config `{ mode: single|multiple, disallowEmpty, behavior: replace|toggle }` (S1, S3). Default table: clips multiple/replace; tracks single (D2 always one active track); devices single; automation points multiple; mask nodes single.
2. All mutators are one of `set | add | toggle | extend | selectAll | clear | invert` (S2). The spec for each object lists which verbs it supports and the exact store action each maps to.
3. `current` (focus end), not array index 0, drives the LAYER panel's primary target when several clips are selected (S9, S1) - state this under D3's panel behavior.
4. Range-extend on the timeline is **geometric** (rectangle between anchor clip and target clip across tracks) unless the spec explicitly chooses flat order; record the choice and the fixture (S1; Problem 3). This fixes an existing gesture, so it stays in the main body as an open question for the owner: **OQ1 flat-order vs rectangle**.
5. Mouse modifier table (single source, S4, S7): plain = set; Shift = extend; Cmd/Ctrl = toggle; marquee drag = replace (additive with Shift); Alt during any drag = snap bypass only (matches D12). Cmd/Ctrl must NOT also mean snap-bypass on the same gesture as toggle; resolve by moving snap-bypass to Alt everywhere (Clip.tsx:40-45 currently uses Cmd) - flag as a behavior change, owner veto-by-exception.
6. Press/release rule for multi-selection drag (S6, S8): pressing on a member of a multi-selection never changes the selection; a release without drag collapses to that clip; Cmd-click on a selected member removes it on release.
7. Right-click rule (Problem 5): if the target is in the selection, keep the selection; else replace with the target; applies to every `onContextMenu` owner in `inventory.json` (cross-ref context-menus.md R1).
8. Keyboard selection set (S5, S10): Cmd+A select all in focused collection, Cmd+Shift+A deselect (conflict with `mask_deselect_all` - resolve in the conflict check), Escape ladder defined in keyboard-focus.md section "Escape ladder". Remove the menu label `CmdOrCtrl+A` or bind it - one of the two (Problem 6); the conflict checker in keyboard-focus.md flags this class.
9. Typed clear order for Escape: node/transform box -> mask region -> clip selection -> time-range selection -> (perform panic) (S11).
10. Selection visual = D11 translucency; one table in COMPONENT-SPEC maps each state (selected / active / hover / drop-target) to a token (Problem 8).

## Library evidence (React Aria selection)

| Criterion | Evidence |
|---|---|
| License | Apache-2.0 (`~/Development/_refs/react-spectrum/LICENSE`, file headers) - ADOPT tier. |
| API fit | `SelectionManager`/`Selection` are class-based stately objects (`packages/react-stately/src/selection/`), React-agnostic in logic but typed to a `Collection` of `Key`s and a `KeyboardDelegate`. Fits lists/grids/trees; a 2D timeline (clips positioned in time on lanes) has no ready `ListKeyboardDelegate` - would need a custom delegate for geometric neighbors. |
| Pointer model | `useSelectableItem` couples to `usePress` (press-start vs press-up, long-press, double-click action). Creatrix clips use raw `pointerdown` + manual drag (`Clip.tsx:442-520`, handlers attached in `onPointerDown` at `Clip.tsx:691`); adopting means rewriting the drag entry or using only `SelectionManager` (logic) without the hooks. |
| Bundle | Not measured (no builds allowed). Modular imports: the `react-stately` selection folder is small vs `react-aria` hooks; tree-shakeable ESM. |
| A11y | Best-in-class (aria-selected/multiselectable, virtual focus). |
| Maintenance | Active; repo head commit date 2026-11-04. Recently reorganised into `packages/react-aria` + `react-stately` (old `@react-aria/*` packages are re-export shims, e.g. `@react-aria/selection/src/index.ts`). |
| Neutral summary | Logic layer (Selection/anchor/extend/range) is directly reusable and replaces ~6 store actions; hook layer conflicts with the existing manual pointer pipeline. Cheapest adoption: copy the model, not the hooks. Decision deferred (verdict c). |

## Candidate additions (owner approval required)

1. **Named selection sets / "select similar"** (select all clips on same track, same color, same source - extends the existing `select-by-track` menu item `menu.ts:65`). Blender-style select-similar is new feature scope; not in the roadmap.
2. **Selection history (back/forward through selections)** from Ardour's selection memento (S12). New feature; selection is deliberately not undoable today.
3. **Selection count/summary in status bar** ("3 clips, 2 tracks, 4.2s") - not currently planned.
