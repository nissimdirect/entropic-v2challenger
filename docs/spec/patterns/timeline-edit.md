# Pattern teardown: timeline editing (data model, trim/ripple/roll/slip/slide, edit modes, snap)

Tiers: OpenTimelineIO = ADOPT (Apache-2.0, read freely). Kdenlive, Olive, Ardour = READ (GPL, behavior in own words, no code copied). Refs in `~/Development/_refs/`.

## Problem in Creatrix today

1. **Data model is absolute-position clips, not a sequence.** `Clip` carries `position`, `duration`, `inPoint`, `outPoint` (`shared/types.ts` Clip interface, ~lines 279-282); there are no Gap or Transition items. Fine for D2 (Track = Layer, z-order = row order), but the semantics of "what does move/trim do to neighbours" are implicit in each store action.
2. **Overlap policy is "snap to nearest free slot," never overwrite or insert.** `moveClip` computes sibling ranges and pushes the clip to the closest free position (`stores/timeline.ts:1388-1404`); there is no overwrite/insert/fill edit.
3. **Ripple trim exists in the store but has no UI caller.** `rippleTrimClipOut` is declared and implemented (`stores/timeline.ts:222`, `:1648`) but grep shows no non-test caller; trim handles always call plain `trimClipIn`/`trimClipOut` (`components/timeline/Clip.tsx:627`, `:653`). Ripple only reaches users via the Ripple Delete menu item/tool (`Clip.tsx:231-232`, `:332-335` -> `rippleRemoveClip`).
4. **Edit modes are separate cursor tools, not a mode.** `cursorTool` (`stores/layout.ts:42,181`) with `razor`, `ripple-delete`, `slip`, `slide` branches in `Clip.tsx:315-388`. There is no roll (neighbour-coupled trim), and no ripple-vs-normal toggle for move/trim.
5. **Snap is a clean pure function** (`utils/snap-candidates.ts:67` `computeSnapPosition`, `:141` `collectClipEdges`; 8 px threshold converted via zoom, `:75`) invoked by `snapPosition` in `Clip.tsx:49-79`; Cmd/Ctrl bypasses all snapping (`Clip.tsx:499,625,651`). Snap sources: clip edges, playhead, markers, grid (`Clip.tsx:62-74`). No snap-strength notion (just on/off + quantize).
6. **Drag commits are per-move** (see `undo.md` Problem 1); trim/move don't preview in a ghost.
7. **No clip groups.** `groupId` in the stores refers to effect groups (`stores/project.ts:134,611`), not linked clips. Audio/video clips are linked only through track structure.
8. Locking is enforced per action (`isClipEffectivelyLocked`, `stores/timeline.ts:1375-1378`, `:1560`, `:1730`); T3 rule "ripple skips locked tracks" is stated in comments only for ripple-delete.

## Recommendation for the spec

1. **Edit-verb table (E4, E2).** Spec each existing verb (move, trim in/out, split, slip, slide, ripple-delete, ripple-trim) against OTIO's definitions: what moves, what is clamped by available media, what is untouched. Each verb states its locked-track behavior (Problem 8).
2. **State the clamp rule once (E2):** all edits clamp `inPoint >= 0` and `outPoint <= assetLength`; rejected edits return the achieved value so the gesture can show it (E7).
3. **Wire or retire ripple-trim (Problem 3).** Spec whether trim-out with a modifier or a rail "ripple" tool exposes `rippleTrimClipOut`; do not leave an unreachable store action. The modifier/tool choice must go through the keyboard-conflict check (E16).
4. **Roll is the one missing standard trim verb (E4, E11).** If trim set is meant to be complete for a D1 "Ableton x Photoshop" editor, it is a rail tool in the TRIM group (D4a) rather than a global mode (E13).
5. **Overlap policy is explicit (Problem 2, E4).** Spec states current behavior (snap to nearest free slot) as the default; overwrite/insert are not specced as existing behavior.
6. **Ghost preview for move/trim (E12, D11):** during drag, show translucent ghost at proposed position; real clip/store untouched until release (ties to `undo.md` rec 1).
7. **Snap source tagging (E14):** `computeSnapPosition` returns which source won so the UI can highlight it; Cmd/Ctrl bypass stays (`Clip.tsx:499`).
8. **Time unit decision recorded (E3):** seconds-as-float stays for v1 unless the owner picks frame-exact; spec lists it as an open decision.

## Library evidence (OpenTimelineIO, ADOPT tier)

- Fit: algorithm *definitions* (editAlgorithm.h) are language-neutral and directly usable as test oracles; data-model *code* is C++/Python bindings. Nothing in the Creatrix frontend (TypeScript/Zustand) can consume it at runtime without a bridge.
- API: sequential items with gaps vs Creatrix absolute positions - an adapter would be lossy (E1).
- Interchange: OTIO is also an interchange format (`src/otio` adapters not read in this pass); worth a separate look if EDL/AAF/FCP export is ever planned.
- License Apache-2.0; no bundle impact because use is documentation/oracle only.
- Verdict-neutral: recommend using OTIO as spec vocabulary, not as a dependency.

## Candidate additions (owner approval required)

- **Roll tool** (E4, E11): not present today.
- **Insert / overwrite / fill edits** (E4): Creatrix only has snap-to-free-slot.
- **Range lift / remove-space / insert-space on `selectionRegion`** (E10).
- **Linked clip groups with single-item override modifier** (E9).
- **Global Ripple/Slide/Lock edit-mode toggle** (E13) - likely conflicts with D4a grouped rail; needs owner ruling.
- **Magnetic snap (pull during motion)** (E14).
