# Pattern teardown: keyboard and focus (plus the automated hotkey conflict check)

Scope: how keys are routed (contexts, precedence, text-input guard), how focus is contained/restored/shown, and a design for an automated hotkey conflict check. Feeds systems/focus-keyboard, O11 (Tool), and every object spec's hotkey rows.
Tiers: React Aria, Blueprint, cmdk = ADOPT. Blender, Ardour = GPL, patterns only (own words). REAPER `reaper-kb.ini` = OBSERVE tier, **not read in this pass** (Phase-2 step 2); gap noted at the end.
Refs: `~/Development/_refs/{react-spectrum,blueprint,cmdk,blender,ardour}` (read-only).

## Problem in Creatrix today

1. **Three overlapping key-dispatch systems, one precedence order that is implicit.** (a) `shortcutRegistry` (`frontend/src/renderer/utils/shortcuts.ts:159-186`) driven from one capture-phase window listener (`App.tsx:1194`, listener registered capture=true at the end of the keydown effect); (b) hard-coded branches before it in the same handler: perform-armed pad keys, a 4-level Escape ladder, Space (`App.tsx:1067-1148`); note the whole handler returns immediately when the target is INPUT/TEXTAREA/SELECT (`App.tsx:1058-1059`), so even Cmd+S cannot fire from a focused text field; (c) 30 component-local handlers (`inventory.json` `hotkeys.rawKeyHandlers`: 9 `window` listeners (8 keydown, 1 keyup), 5 `document`, 1 element listener, 15 JSX `onKeyDown`), several on `window` which fire in addition to (a), e.g. `Timeline.tsx:114` Escape, `AutomationLane.tsx:378` Escape, `AutomationTransformBox.tsx:261` Escape, `RoutingCanvas.tsx:244` Escape, `BoundingBoxOverlay.tsx:209` arrows, `MaskSelectOverlay.tsx:445` Enter/Escape.
2. **The context model is declared but dead.** `ShortcutContext = 'normal' | 'perform' | 'text-input'` (`shortcuts.ts:5`); every one of the 51 registry rows is `context: 'normal'` (`default-shortcuts.ts`); `setContext()` exists (`shortcuts.ts:98`) but has **no caller** (grep: only the definition). Perform mode is instead a track-selection test inside `App.tsx` (`isArmed`, `App.tsx:1067`). So `'perform'` and `'text-input'` bindings are impossible today and the same key cannot mean two things per surface.
3. **Silent last-wins on duplicate keys.** `rebuildKeyIndex` does `keyToAction.set(key, action)` for every binding (`shortcuts.ts:190-195`); two actions with the same effective key overwrite each other with no error or warning. `getConflicts` (`shortcuts.ts:131-140`) is only consulted by `ShortcutEditor` at capture time (`ShortcutEditor.tsx:40-44`). Defaults are not checked at load; the inventory reports `conflicts: []` only because the current table is hand-curated (comment at `default-shortcuts.ts` tool block "Conflict-checked: all 11 keys unique").
4. **Dead and phantom bindings.** `defaultsWithoutHandler` (6): `tool_slip` (s), `tool_slide` (d), `grid_up` (]), `grid_down` ([), `toggle_popout`, `tool_escape_select` (inventory `hotkeys.defaultsWithoutHandler`, `default-shortcuts.ts:73,74,90-93`). `handlersWithoutDefault` (2): `preferences`, `about` (`App.tsx:787-788`). Menu labels with no binding: "Select All Clips CmdOrCtrl+A" (`menu.ts:61`), "Save As... CmdOrCtrl+Shift+S" (`menu.ts:33`) (verified by normalising every `\tCmdOrCtrl+X` menu label against the registry: 17 of 19 labelled shortcuts match, those two do not). "Toggle Automation A" and "Toggle Focus Mode F" are bare letters shown in the menu with no accelerator (`menu.ts:125-126`).
5. **Normalisation order differs from authoring order.** Defaults are authored `meta+shift+z`, but `normalizeKeyString` re-orders to ctrl, alt, shift, meta -> `shift+meta+z` (`shortcuts.ts:35,50-55`). Any external checker must reuse that exact function or it will report false mismatches.
6. **Text-input guard is tag-based, duplicated and coarser than the registry's.** Registry: INPUT/TEXTAREA/contenteditable (`shortcuts.ts:162-166`) with per-binding `context: 'text-input'` escape hatch (unused). App handler: INPUT/TEXTAREA/SELECT, all keys including modified ones, no escape hatch (`App.tsx:1058-1059`, keyup `App.tsx:1166`); contenteditable is not tested there. Composition (IME) is not guarded anywhere in `src/renderer` (grep `isComposing|229`: none).
7. **Focus handling is per-dialog.** `useModalBehavior` (trap, initial focus, restore) is used by 10 component files (`hooks/useModalBehavior.ts:1-40`; PUX.2); `ContextMenu` saves/restores its invoker itself (`ContextMenu.tsx:39,62-74`); `ToolRail` flyout has its own roving index (`ToolRail.tsx:195-225`); there is no shared focus-scope, no documented tab order for the app shell, and 12 `:focus-visible` rules in `styles/global.css` (grep; per-component stylesheets not surveyed) against 157 components.
8. **Escape has a ladder, but only for part of the Escape handlers.** `App.tsx:1103-1140` implements L2 mask, L3 tool mode, L4 clips, then stop; the other Escape listeners (`Timeline.tsx:114` selection range, `AutomationLane.tsx:378`, `AutomationTransformBox.tsx:261`, `RoutingCanvas.tsx:244`, `ToolRail.tsx:152`, `DemosDrawer.tsx:189`, `ShortcutEditor.tsx:53`, `ContextMenu.tsx:100`) are independent, so ordering depends on listener registration, not on "innermost closes first". The registry row `tool_escape_select` (`escape`) can never fire: the App Escape branch always returns first (`App.tsx:1117-1121` says so) - a phantom binding the checker must flag as SHADOWED-DEAD.
9. **Hard-coded geometry in menu positioning** `menuW=180`, `menuH=items*28` (`ContextMenu.tsx:42-45`) - see context-menus.md.

## Recommendation for the spec

1. **Name the precedence**, top wins (K4, K6): (1) IME composition -> ignore (K11); (2) modal layer (open dialog/menu/palette/active drag) owns its keys incl. Escape/Enter/Tab; (3) focused text input: modified keys (not Shift-only) may fall through to global app shortcuts, unmodified keys never (K3); (4) focused-surface bindings (timeline, automation lane, preview, device chain, library); (5) global registry. One dispatcher, listeners on `window` removed in favour of surface-scoped handlers (K2). Cite Problem 1.
2. **Make the context model real** (Problem 2, K4, K6): contexts are *surfaces/owners* (global, timeline, automation lane, preview/mask, device chain, library/browser, perform) plus *modes* (perform armed, text-input, modal-drag, dialog). Each registry row gets `context: <owner or mode>`; `setContext` is replaced by derived state (focused surface + mode), not manual set/unset.
3. **Registry rows must be complete**: `{action, keys, owner/context, label, category, repeat?, allowInInput?, menuId?}` (K2, K3, K12). Menu items reference the action id; the label shortcut is *generated* from the registry, never typed (K6, K7; fixes Problem 4 "Select All Clips", "Save As").
4. **Extend, do not invent, the Escape ladder** (K4, Problem 8; selection.md Recommendation 9): keep the existing App.tsx order (L1 marquee, L2 mask, L3 tool mode, L4 clips) and add above/below it: transient popup (menu/flyout) and text edit first; active drag and transform box/node edit next; time-range selection after clips; transport stop last. Perform-armed branch unchanged. One dispatcher walks the ladder (surface modules register `canHandleEscape()/handleEscape()` instead of owning window listeners). Delete the `tool_escape_select` registry row or move it to the ladder as documentation.
5. **Focus**: one `FocusScope`-style primitive with `contain`, `restoreFocus`, `autoFocus` (K8) replacing `useModalBehavior`, ContextMenu invoker restore and flyout restore; focus ring shown for keyboard modality only (K9). Tab order for the shell is documented: rail -> browser -> preview -> transport -> arrangement -> LAYER panel -> device chain -> status bar (derive from D10 rail + S01-S10, confirm with owner).
6. **Composites** follow one keyboard contract (K10): Arrow moves, Home/End jump, type-ahead for lists, wrap off by default.
7. **Reserved-key list** (cannot be rebound, cannot be reused by any binding): macOS system keys (Cmd+M minimize, Cmd+H hide, Cmd+Q quit, Cmd+Tab) per `default-shortcuts.ts` comment F-0516-8; Space = play/pause bare; Escape = ladder; Tab/Shift+Tab = focus traversal. The conflict checker enforces this list.
8. **Help/shortcut UI** derived from the registry (K7); Preferences > Shortcuts shows context column and conflict badges.
9. **Duplicate and dead rows are build failures** (K14, Problem 3, 4): see the checker below.

## Automated hotkey conflict check (design only, no product code)

### Purpose
Fail CI when the set of keyboard bindings contains a conflict, a dead binding, a phantom label, or a reserved-key violation. It must run without launching Electron, as a script alongside `docs/spec/tools/coverage.mjs` and the ratchet scripts (`frontend/scripts/ui-ratchets.sh`), reading source and `inventory.json` only.

### Inputs (three sources, one canonical model)
| Source | Location | What it gives | Extraction |
|---|---|---|---|
| Registry | `frontend/src/renderer/utils/default-shortcuts.ts` (51 rows today) | `action`, `keys`, `category`, `label`, `context` | Import the array (TS) or reuse `inventory.json` `hotkeys.registry` (already has `at` file:line). Keys normalised with the **same** `normalizeKeyString` from `shortcuts.ts:50` (Problem 5). |
| Handlers | `inventory.json` `hotkeys.registered` (47) | which actions have a registered callback, `at` | Used for dead/phantom detection (`defaultsWithoutHandler`, `handlersWithoutDefault`). |
| Raw handlers | `inventory.json` `hotkeys.rawKeyHandlers` (30) | `at`, `kind` (window/document listener vs JSX onKeyDown), `component`, `keys` as `key:`/`code:` tokens | Treated as *unregistered bindings*: each token becomes a pseudo-binding with owner = component and scope derived from `kind`. |
| Menu labels | `frontend/src/main/menu.ts` | `label` text with `\tCmdOrCtrl+X` suffix, menu action id | Regex over `label: '...\t...'`; translate `CmdOrCtrl` -> `meta` (mac) / `ctrl`, parse with the same DSL (K1). Roles (undo/redo/cut/copy/paste/delete) contribute implicit OS bindings (Cmd+Z, Cmd+Shift+Z, Cmd+X/C/V). |
| Reserved list | new small JSON owned by the spec | OS-reserved and ladder keys (Recommendation 7) | Static. |

### Canonical record
`Binding { id, source: registry|raw|menu|os|reserved, key: {mods:set, key:string, event: keydown|keyup|repeat?}, scopes: set<Scope>, mode: set<Mode>, textInput: allow|deny, at: file:line }`.
- `key.key` unifies `e.key` and `e.code` tokens: `code:Space` -> `space`, `code:Escape`/`key:Escape` -> `escape`, `key:ArrowUp` -> `arrowup`, letters lowercase. Raw handlers using `code:` for pads (App.tsx perform branch, `App.tsx:1067-1090`) are tagged `layout: physical` and are compared by physical key only against other physical bindings plus the letter on the US layout (assumption flagged).

### Context model
Scopes form a tree, a binding in a scope is active whenever its scope or any descendant is focused:
`global > surface{timeline, automation-lane, preview, mask-overlay, device-chain, library, routing-canvas, rail, dialog} > widget{knob, slider, number-input, marker-name-input, clip-rename-input, ...}`.
Modes (orthogonal flags): `perform-armed`, `text-input`, `modal-drag`, `dialog-open`, `menu-open`.
Derivation (from `rawKeyHandlers`): `window`/`document` listener -> scope = `global` **unless** the component maps to a surface via a small table (`AutomationLane` -> automation-lane, `Timeline` -> timeline, `RoutingCanvas` -> routing-canvas, `MaskSelectOverlay`/`BoundingBoxOverlay` -> preview, `DemosDrawer`/`EffectBrowser` -> library, `ToolRail` -> rail); JSX `onKeyDown` -> scope = widget/surface of that component (it only sees events while focused inside). `text-input` mode: JSX handlers on `<input>` elements and `NumberInput`, `MarkerFlag`, `Clip` rename (`Clip.tsx:729`), `Track.tsx:544` are `textInput: own` (they consume keys when focused).
Two bindings can **co-fire** if their scopes are in an ancestor/descendant relation or both global, and their modes intersect. Disjoint surfaces (timeline vs preview) never co-fire. This is the Blender idea of "keymaps that can be active together" (K4, K5) and Ardour's owner ordering (K6).

### Algorithm
1. **Normalise** every source to `Binding` (above). Registry/menu strings go through the shared parser (K1); `CmdOrCtrl` expands to meta.
2. **Bucket** by `key` (mods+key+event). Within each bucket, compare pairs.
3. **Classify each pair** (A, B) with `coFire(A,B)` = scopes related OR both global, AND modes intersect:
   - **HARD conflict (error):** coFire and both are `registry`/`menu`/`os`/`reserved` with *different* actions (e.g. registry `meta+shift+a` `mask_deselect_all` vs a proposed Select-deselect). Includes registry vs OS implicit menu roles.
   - **SHADOWED-DEAD (error):** a registry row whose key is unconditionally consumed earlier in the dispatch order by a raw branch (today `tool_escape_select` vs the App Escape branch, and Space vs `play_pause` which both exist: `App.tsx` direct-Space branch precedes the registry). Detected by listing raw handler keys that end in `return` before the registry call (App.tsx branches annotated in the inventory).
   - **SHADOW (error unless allowlisted):** a registry/global binding's key equals a raw handler's key with coFire true and the raw handler does not `continuePropagation`/is capture-phase after the registry (Problem 1: e.g. `escape` registry `tool_escape_select` vs `Timeline.tsx:114` vs `RoutingCanvas.tsx:244` vs `AutomationLane.tsx:378`). Resolution recorded in an allowlist file entry `{key, winner, loser, reason}` that must cite the Escape ladder or surface-priority rule.
   - **TEXT-INPUT LEAK (error):** bare (no mods, or Shift-only) printable key in a global registry binding with `textInput: allow` unless the row is flagged `allowInInput` (K3). Registry today relies on the tag guard; this check enforces the flag for new rows.
   - **PRESS/RELEASE/DRAG (K5):** keyup vs keydown on the same key never conflict; `repeat:true` vs `false` conflict only if the handler is not idempotent (warn).
   - **DUPLICATE (error):** two registry rows with identical normalised key and overlapping `context` (the silent last-wins case, `shortcuts.ts:190`).
4. **Dead / phantom (per-row checks, not pairwise):**
   - registry action without a `registered` handler -> `DEAD-BINDING` (today 6).
   - `registered` handler without registry row and not a menu-only action -> `PHANTOM-HANDLER` (today `preferences`, `about`, allowlist if intentional).
   - menu label shortcut with no registry row of the same normalised key -> `LABEL-ONLY` (today: Save As, Select All Clips); registry row with a menu item but different key text -> `LABEL-MISMATCH`.
   - menu item with an accelerator-less bare-key label ("Toggle Focus Mode\tF") is allowed only if the registry row exists (it does).
5. **Reserved-key rule:** any binding whose key is in the reserved list (OS-reserved, Escape ladder, Tab traversal, Space bare) from a source other than its owner -> error.
6. **Mnemonic collisions (warn):** same bare letter used in different surface scopes (`a` toggle_automation vs a future select verb in S10); informational so authors see reuse.
7. **Output:** deterministic JSON + table (`key | A | B | class | resolution`), exit code non-zero on errors; counts printed per class. Baseline/ratchet file (same pattern as `frontend/.a11y-ceiling`): known debt allowed up to a ceiling that only decreases; any new class instance fails.
8. **Self-test fixtures** (the check needs to prove it can fail): synthetic registry with two rows on `meta+k`; a raw `window` Escape listener added; a menu label `CmdOrCtrl+Q`; a bare `m` with `textInput: allow`; each must produce exactly its class. Per Rule 2, run chaos cases: key written in different modifier order (`meta+shift+z` vs `shift+meta+z`), uppercase letters, `+` and `=` keys (`meta+=` contains `=`; split on `+` must handle `meta++`), `code:` vs `key:` tokens.

### Open design questions for the owner
- Q1 Layout: compare `code:` bindings (pads) against `key:` bindings by US layout or treat as separate namespaces? (default: separate namespace, pads documented as physical).
- Q2 Is Shift-only-modified printable key text-input-safe? (Ardour treats Shift as non-modifier for this routing, `ardour_ui_keys.cc` `mask = ... & ~(SHIFT|LOCK)`; default: yes, same.)
- Q3 Scope table for components -> surfaces is hand-maintained (30 rows); acceptable or derive from the surface specs S01-S10?
