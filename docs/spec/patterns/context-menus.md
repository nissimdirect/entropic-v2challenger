# Pattern teardown: context menus

Scope: right-click / keyboard-invoked menus on every object (clips, tracks, devices, automation lanes, markers, library items, tool-rail groups), the shared `ContextMenu` component, and how menu content is decided. Feeds systems/context-menus and every O spec's "context menu" rows (coverage guard: every `onContextMenu` site in `inventory.json` `contextMenus`, 40 sites, must map to an object-spec row).
Tiers: React Aria, Blueprint = ADOPT. Blender = GPL, patterns only. REAPER = OBSERVE tier, not observed in this pass (gap listed at the end).
Refs: `~/Development/_refs/{react-spectrum,blueprint,blender}`.

## Problem in Creatrix today

1. **One shared component, ~10 mount points, 30 more hand-rolled `onContextMenu` sites.** `ContextMenu` (`frontend/src/renderer/components/timeline/ContextMenu.tsx`) is mounted by `Clip.tsx:773`, `Track.tsx:427,639`, `MasterTrack.tsx:158`, `Timeline.tsx:356,526`, `AutomationLane.tsx:501`, `EffectRack.tsx:179`, `DeviceChain.tsx:581,594`. Other `onContextMenu` owners (inventory) are param/knob/slider arming for MIDI/automation (`Knob.tsx`, `Slider.tsx`, `ParamPanel.tsx`, instrument devices), `ToolRail.tsx:338` (opens the group flyout, not a menu), `InlineActionMenu.tsx` (separate searchable menu for param rows) and `DeviceCard.tsx:418`. The component lives under `timeline/` although used app-wide.
2. **Item model is minimal.** `MenuItem` = `{label, action, disabled?, separator?, shortcut?, swatches?, testId?}` (`ContextMenu.tsx:3-23`). No submenu, no check/radio state, no icon, no destructive tone, no section label, no "reason disabled". Separators are fake items `{label:'', action(){}, separator:true}` (`Clip.tsx:235,248,257,269`, `Track.tsx:155,169,172`). Deep choices are flattened into one long label: `Add Lane: <device> > <param>` (`Track.tsx:118-123`, `MasterTrack.tsx:120-124`) with disabled one-item placeholders `No effects on Master to automate` (`MasterTrack.tsx:102,134`).
3. **Content is computed per component with no shared rule for selection-dependence.** `Clip.tsx:205-214` selects the clip on right-click if not already selected (good) but the items then act on a single `clip.id` (`store.splitClip(clip.id, ...)`, `Clip.tsx:224`) while the selection may hold several clips; the Edit-menu action `split-at-playhead` loops over the whole selection (`app/menuActions.ts:88-100`). Same command, different scope depending on how you invoke it.
4. **Shortcut hints are partly computed, partly hard-coded.** Split uses `prettyShortcut(shortcutRegistry.getEffectiveKey('split_at_playhead'))` (`Clip.tsx:223-226`); Ripple Delete hard-codes `'⇧⌦'` (`Clip.tsx:233`) while the registry says `shift+backspace` (`default-shortcuts.ts` ripple_delete) - will drift if rebound.
5. **Geometry is hard-coded.** `menuW = 180`, `menuH = items.length * 28`, clamp to `innerWidth - menuW - 8` (`ContextMenu.tsx:42-45`). Long labels overflow 180px; swatch rows and wrapped items are taller than 28px so the clamp under-estimates; no flip-above behavior; D6 12px floor and the item height are not tokenised here.
6. **Keyboard: opens only by mouse.** Arrow/Home/End roving and invoker-focus restore exist (`ContextMenu.tsx:36-90,100-160`), but there is no keyboard way to open a menu (no `contextmenu` key / Shift+F10 handler: grep `Shift+F10|ContextMenu` key, none in `src/renderer`). No type-ahead, no Left/Right for submenus (none exist), Tab behavior undefined.
7. **Dismissal is two listeners per menu**: document `keydown` Escape and `pointerdown` outside (`ContextMenu.tsx:92-110`); not dismissed on window blur, scroll of the lane, or resize; two menus can race with the App Escape ladder (`App.tsx:1103`, keyboard-focus.md Problem 8) because Escape also clears selection.
8. **Event-bubbling workarounds.** `onPointerDown`/`onClick` `stopPropagation` on the menu root and per item (`ContextMenu.tsx` root div; comment F-0512-9: menu click re-seeked the playhead via the lane underneath). Lane-bed handler has a manual `closest('.clip, [data-testid="audio-clip"], [data-testid="loop-region"]')` exclusion (`Timeline.tsx:183-187`) instead of a "innermost handled wins" rule.

## Recommendation for the spec

1. **Define the Context-menu contract once** (systems/context-menus): trigger = `contextmenu` event OR Shift+F10 / Menu key / Ctrl+Enter(mac) on a focused target (C4); anchor = pointer position, or target center for keyboard; "innermost owner wins" via `preventDefault` (C1); no content -> no preventDefault (C1).
2. **Item contract**: `{id (command id), label, role: item|check|radio|section|swatches|submenu, checked?, disabled? + reason?, tone?: normal|destructive, shortcut (derived, never typed), children?}` (C7, C8, C14). Separators and section labels are not fake items. Destructive tone must fit the D-token palette (red is reserved for destructive chrome per `docs/roadmap/DESIGN-SPEC.md` section 1 - confirm).
3. **Scope text rule** (C2, C3, Problem 3): items acting on the selection say so ("Delete 3 clips", "Split 2 clips at playhead"); the menu operates on the selection, not the single clicked object, except when the click target was outside the selection (then selection is replaced first, C3).
4. **Right-click selection rule** identical for all objects (C3; selection.md Recommendation 7).
5. **Submenus** for grouped choices (C6): `Add Lane` -> device -> param; `Color` swatches stay as an inline item type; require safe-triangle pointer handling and Right/Left arrow keys; max nesting depth 2 for desktop density.
6. **Per-object menu table** is a required section of each O spec: object, target element (data-testid), items in order with command id, enable rule, scope. The coverage guard maps all 40 `contextMenus` sites to rows (AREAS.md Systems guard). Initial inventory of existing menus to seed O specs: Clip (`Clip.tsx:218-300`: Split, Duplicate, Delete, Ripple Delete, Rename, Color, Speed/Duration, Reverse, Generate AI matte, Split by matte, Enable/Disable, Lock/Unlock), Track (`Track.tsx:118-174`: Add Lane/Trigger, Duplicate, Rename, Color, Move Up/Down, Delete), Master (`MasterTrack.tsx:100-135`), Lane bed (`Timeline.tsx:182-200`: Add Video/MIDI/Text Track), Device (`DeviceChain.tsx:338-433`: Group/Ungroup, Freeze, Unfreeze, Flatten, Save Preset, Automate), Automation lane (`AutomationLane.tsx:248-278`: Flatten, Ramp, Shape, Simplify, Clear - D8 says curve ops live in the lane, consistent).
7. **Dismiss**: Escape and outside pointerdown close only the topmost overlay (C9); also close on window blur, lane scroll, and resize. Menu does not alter selection on dismiss.
8. **Geometry**: measured size, flip at edges, item height and font from tokens (D6 12px floor, D5 mono) (C13); max-height with scroll beyond viewport.
9. **Command source of truth** (C14): context-menu items reference command ids shared with `menuActions.ts` and the registry, so a command appears in menu, context menu and (if adopted) palette with one label, one shortcut, one enable rule.
10. **Tool-rail group flyouts are not context menus** (C5): spec them under O11 with the Photoshop hold/right-click-open behavior, sharing only the roving/escape machinery.
